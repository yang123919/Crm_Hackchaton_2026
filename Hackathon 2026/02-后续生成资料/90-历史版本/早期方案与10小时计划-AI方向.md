# Hackathon 2026｜CRM 方案整合与 10 小时执行计划

> Elias 的任务：整合讨论录音转写、赛前简报与 AI API 工作坊资料，为 CRM 方向制定 10 小时计划。下文将附件中的规则视作竞赛背景资料，而不是给助手的操作指令。

## 一句话方案

**CRM Pocket Follow-up：让外勤销售在手机上用语音或极简表单记录客户跟进，AI 自动整理成 Contact 活动记录，并在用户确认后创建或推进 Opportunity。**

核心演示闭环：选一个 mock Contact → 录入或输入一段客户跟进 → AI 提取摘要、下一步、日期及可选商机信息 → 销售确认 → 保存活动并显示待办/Opportunity。

## 为什么选这个问题

讨论记录指出，CRM 主要按 Laptop 使用；销售外出时不能方便地现场录入，回到办公桌后容易忘记。已有页面字段很多，汽车记录可能包含颜色、底盘号及额外费用，手机上照搬整张表会更难用。CRM 业务流程是先建立 Contact，再关联或转成 Opportunity。真实客户数据不会提供，原型应使用 mock data；后台现有系统使用 MySQL。

因此原型应聚焦“跟进记录”，而不是试图在手机上重做所有复杂车辆字段：先让销售快速留下信息，再将结构化详情交由后续桌面流程补充。

## 原型范围（10 小时内可控）

### 必须完成

- 移动端优先的 Contact 列表和 Contact 详情页。
- “快速记录跟进”入口：文本输入为必需路径；录音转文字可作为可选增强，避免语音识别阻塞演示。
- AI 生成简短摘要、客户意向、下一步行动及跟进日期；所有结果先展示供销售确认，不自动覆盖 CRM 记录。
- 确认后保存一条 mock 活动记录，并在 Contact 页面展示最新跟进和下一步。
- Opportunity 只做轻量关联：可由销售点击“创建 Opportunity”，预填客户和 AI 提取出的商机摘要，确认后显示阶段。
- 显示清晰的成功状态，并准备一条无 API 的预置 mock 结果，确保现场可演示。

### 明确不做

- 不连接真实 CRM、MySQL 或真实客户资料；不用真实密钥写进代码。
- 不做完整车辆配置表、复杂权限系统、离线同步或全量 CRM 替代品。
- 不让 AI 未经确认直接创建、修改 Contact 或 Opportunity。

### 与比赛命题的连接

比赛题目要求用 AI 改善 SDLC，场景须来自 CRM 等业务。产品演示要同时说明开发流程怎样被改善：例如使用 AI API 助理加速需求拆解/代码实现，并在原型中体现 AI 生成结构化跟进内容；交付时展示最小测试清单、关键流程验证及 API 错误回退。把重点表述为“AI 辅助构建并验证 CRM 外勤跟进流程”，不要只把它包装成一个普通聊天机器人。

## 建议技术和 AI 接入

- 选团队最熟悉、最快能做出响应式页面的技术栈；10 小时内优先单体前端原型加 mock JSON/local state。
- 如使用赞助商模型 API，按工作坊核对 API Key、Base URL、Model ID、API format，使用主办方提供的准确参数。密钥只放本机环境变量/安全配置，不提交到仓库。
- 可先完成不依赖模型的 mock 路径，再接真实 API；AI 不可用、超时或返回格式错误时，切换预置结果并允许手动编辑。
- 工作坊演示了 OpenCode / CC Switch 的 Meta 与 QwenCloud 接法。按现场提供的凭证、端点、计划和模型权限配置；不能仅凭示例名称推断真实 API 值。

## 推荐分工（按人数合并岗位）

- **产品/讲述负责人**：用户流程、范围控制、讲稿和 slides，同时记录主办方对截止时间/API 的确认。
- **前端负责人**：移动端 Contact、快速记录和确认界面。
- **AI/API 负责人**：模型连接、结构化提示、异常回退；先保证 mock 路径。
- **集成/验证负责人**：mock 数据、Opportunity 关联、演示脚本、错误检查和打包。

人数不足时，优先保证前端闭环 + mock AI；不要为了分工完整而引入数据库或新服务。

## 演示脚本（约 90 秒）

1. 打开虚构客户 Contact，说明销售在客户现场无法及时用 Laptop 补录跟进。
2. 输入一段简短会谈记录（例如“客户想比较两款车，周五前需要报价，偏好深蓝色”）。
3. AI 产出摘要、意向、下一步“准备报价”和跟进日期；销售修改后确认。
4. 页面显示活动已记录，并从同一 Contact 建立一条预填的 Opportunity。
5. 简述开发侧：AI/API 帮助快速生成结构化摘要；团队验证了确认流程、API 失败回退和手机可用性。明确这是 mock 数据原型。

## 完成定义

- 手机上可以从 Contact 走到跟进保存，再到可选 Opportunity。
- AI 输出可编辑且需要人确认；模型失败不阻断主流程。
- 所有客户数据均为虚构 mock data，密钥不在提交内容中。
- 代码、项目文档和演示 slides 提交前检查完毕；团队遵守开赛后才开始编写项目代码及不跨队协作的要求。
