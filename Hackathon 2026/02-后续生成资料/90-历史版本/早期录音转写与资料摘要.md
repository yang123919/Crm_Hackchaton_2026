## 资料二：Connecting AI API Workshop

### 核心概念

- **Model（模型）**：生成回答或请求工具操作的 AI，例如 Qwen3.8 Max、Muse Spark Contributor。
- **Provider（服务提供方）**：提供 API 访问和用量账户的服务，例如 QwenCloud、Meta Model API。
- **Harness（开发工具/代理运行环境）**：管理项目文件、工具及开发循环的应用，例如 OpenCode、Claude Code 或 Codex。
- 一次请求链路示例：OpenCode 将编码请求经由 QwenCloud 发给 Qwen3.8 Max。

### API 连接参数

连接时需匹配 **API Key、Base URL、Model ID、API format**。工作坊强调使用同一组提供的准确密钥、端点和模型 ID。Provider 配置名用于识别连接；端点和密钥设置地址及凭证；模型列表配置可选模型。

### 配置流程概要

1. 在 OpenCode 中使用 Meta：搜索并选择 Meta，按提示输入赞助方 API key，再从模型选择器选 `muse-spark-1.3-contributor`。
2. 此安装中的 OpenCode provider 目录没有 QwenCloud 条目，因此通过 CC Switch 添加：OpenCode / Add Provider / QwenCloud。
3. 选择匹配的 Token Plan 或 pay-as-you-go 方案；填写 Provider Key `gcr-qwen` 和赞助方 API key；核对 endpoint 与允许使用的模型后添加。
4. 确认 CC Switch 已保存 OpenCode provider 配置；重新打开 OpenCode，在项目的模型选择器里选择 QwenCloud 下的 `Qwen3.8 Max`。
5. 演示用单个 `index.html` 文件创建标题、按钮和点击提示，再让另一个模型修改标题且保留按钮功能；检查改动、打开页面并实际点击测试。

### 常见问题检查

- **Authentication error**：检查 API key 与对应 endpoint 是否配套。
- **Model unavailable**：确认模型 ID 拼写准确，并检查账户权限。
- **Model missing**：确认配置已保存且已在模型选择器中选中。
- 对话可用还不够：需另外确认文件编辑和结果都可用；可检查 Provider 用量记录，确认请求计入了哪个账户。
